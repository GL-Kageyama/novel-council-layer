# 盲评（双盲）

为使评估不受专有名词——作者名、作品名的声望——所牵引，本层采用**双盲**进行评估。即盲评（输入匿名化）与结构性校准（从评价标准中排除专有名词）。

## 为什么盲评：对锚定偏见的认识

无论是人类还是 AI，都无法避免**对声望的锚定（固定观念）**。这不仅是评价的扭曲，更是**直接损害本项目核心使命——发现被埋没的杰作**的危险。锚定于声望的评价会低估不出名的作品，高估出名的作品。那样的话，本该发现的「被埋没的杰作」将永远无法被发现。

## 第一重盲评：输入匿名化

> **评价仅基于正文。评价者在不了解作者名、作品名、文学史评价的状态下进行评价。**

- **输入匿名化**：在输入评价时，去除作者名、作品名，只传递正文。
- **实现**：使用 `utils/anonymize.py` 进行预处理（用 `--author`、`--title` 指定对象，替换为 `〔匿名〕`）。合议编排器（story-council）仅将**匿名化后的文本**传递给评价者。
- **对评价者的信息限制**：传递类型等必要上下文，但不传递诱导声望的信息。

## 第二重盲评：结构性校准（从评价标准中排除专有名词）

仅靠第一重盲评并不充分。如果评价标准以「像○○的作品」「××的水平」这类专有名词写成，那么即使输入是匿名的，**评价者的判断也会被专有名词的声望所牵引**。因此，要从评价标准本身排除专有名词。

> **评价标准与校准不以专有名词（作者名、作品名），而以结构性描述来规定。**

详见 `references/structural-calibration.md`。

## 应对文体识别（文体计量学）

匿名化并非完美——**文体本身有时会泄露作者身份**。结构性校准也部分应对这一残余风险。即使评价者将文体特征与已知作家联系起来，**只要判断标准是结构性的，评价就会朝向结构，而非声望**。即使识别出「这是著名作家的文体」，也会追问「这个结构能否产生有价值的时间」。

## 移交给 Meta Value Layer

盲评的彻底性（匿名化的疏漏、从上下文泄露声望、评价标准中混入专有名词）由 Phase 4 的 **Meta Value Layer（Bias Detection）** 进行监控。评价的偏差通过基准的不一致分析与评价者之间的分歧来检测。

## 盲评检查清单

在实施评价之前，请确认以下事项：

1. 输入文本中是否残留作者名、作品名（是否执行了 `utils/anonymize.py`）
2. 评价者智能体的提示词/校准中是否混入了专有名词
3. 类型等上下文信息是否包含诱导声望的内容
4. 是否未将评价结果与文学史评价对照（对照仅在评价**之后**、在基准中执行）
